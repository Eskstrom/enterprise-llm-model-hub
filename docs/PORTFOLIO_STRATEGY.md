# Model Portfolio Strategy

## Portfolio thesis

Enterprises do not need maximum model choice by default. They need a small, trusted portfolio that covers meaningful workload differences and can expand when a customer need justifies the operational cost.

## Initial portfolio roles

| Role | Selection criteria | Example use |
| --- | --- | --- |
| Cost-efficient default | Meets standard quality bar at low unit cost | Routine summaries and classification |
| High-quality reasoning route | Strong performance on complex synthesis | High-value analysis and multi-step work |
| Grounded-answer route | Reliable instruction following and citation behavior | Knowledge Q&A |
| Tool-use route | Valid, recoverable function calling | Agentic workflows |

## Model admission criteria

A provider or model enters the portfolio only when it solves a demonstrated customer need and meets capability, reliability, capacity, data-handling, supportability, and commercial requirements.

## Upgrade strategy

Test new models in an isolated evaluation workspace first. Recommend an upgrade only when it clears workload-specific quality thresholds and the performance gain justifies migration, support, and governance cost.

## Capacity planning signal

Forecast demand by workload, not total requests alone. Context size, retries, tool calls, and peak concurrency materially change both cost and provider capacity requirements.
